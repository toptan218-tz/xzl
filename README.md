# 心之力 Taro 源码

根据 `../xzl/index.html` 当前入口实际引用的 H5 文件重建，原 `xzl` 文件夹未修改。使用 Taro 4.3、React 18，同一套页面支持 H5 与微信小程序。未将目录内未被当前入口引用的历史版本混入项目。

## 运行与打包

建议 Node.js 20 或 22 LTS。本次环境为 Node.js 25.2.1，已完成两端构建。

```sh
npm ci
npm run dev:h5
npm run build:h5
npm run build:weapp
npm test
```

- H5 输出：`dist/h5`。上传该目录全部文件至静态服务器，使用 hash 路由。可用 `npm run preview:h5` 在 `http://127.0.0.1:10086` 预览生产包。
- 小程序输出：`dist/weapp`。在微信开发者工具导入本项目根目录，`project.config.json` 已配置输出目录；将 `touristappid` 替换为自己的 AppID 后再进行真实网络、预览和上传验证。
- `dev:h5` 与 `preview:h5` 使用相同端口，同时只运行其中一个。

## 接口配置

默认沿用原包地址：`https://xzl.mopu.top/es/api/v1`，在 `config/index.js` 配置。也可通过构建环境变量 `TARO_APP_API_BASE` 覆盖，例如 PowerShell：

```powershell
$env:TARO_APP_API_BASE = 'https://你的接口域名/es/api/v1'
npm run build:h5
```

H5 跨域部署需要后端允许网站来源，或通过同域反向代理提供接口。浏览器不能通过前端代码绕过 CORS；本地预览的实际接口请求出现网络失败，因此尚未完成真实账号联调。

小程序后台须将 `https://xzl.mopu.top`（或替换后的接口域名）加入 request 合法域名。前端不会关闭域名或证书校验。

接口保留短信发送/登录、令牌刷新、用户信息、观点检索、原文读取、存档统计/分页/编辑/删除、反馈。搜索和原文沿用原包的公开接口调用方式。原包的会员升级没有支付实现，本项目保留“暂未开放”提示。

## 登录行为

- 访客可以直接浏览首页、存档、我的，不会初始化后跳到登录页，也不会静默进行微信登录。
- 首页访客可输入问题并请求检索；公开接口是否接受请求由原服务决定。
- 存档页访客点击“读取我的存档”后才请求接口。
- 接口返回 401 时先按原逻辑尝试刷新令牌；刷新仍失败后弹窗，可选择“暂不登录”或“去登录”。访客遇到其他接口失败，也显示实际错误并提供可取消的登录入口。
- 并发错误合并为一个登录弹窗。取消后停留原页，不清除问题草稿。
- 登录使用 `navigateTo` 保留上一页，新增“返回”按钮；登录成功返回上一页，直接打开登录页时返回首页。
- 登录页的验证码/账号错误直接显示在表单中，避免再次弹出登录提示。

## 样式与小程序兼容

保留原包的颜色、字号、布局、文案、登录背景、阅读卡片和反馈页面样式。使用 Taro 组件和请求/存储/导航 API，不依赖浏览器 DOM、localStorage 或 fetch。通过共享组件类名适配 H5 自定义元素与小程序原生组件；关闭二次像素换算，保留原包已换算后的 CSS 像素尺寸，并保留安全区与手机/桌面断点。

登录页及其原始大图放入 `pages/login` 分包，避免超过小程序主包限制。构建后仍需在微信开发者工具及真机检查字体回退、键盘遮挡、安全区和不同微信基础库；本次未执行微信真机测试。

这是从发布文件重建的可编辑工程，并非找回原始仓库；原变量名、开发注释和后端源码无法从 H5 发布物完整恢复。自动测试覆盖关键认证行为，两端构建已验证；短信真实发送、登录后存档操作和微信真机效果需要有效账号、AppID 与可用接口进一步验收。

浏览器已实际验证：访客首页正常显示，390×844 布局正常；访客请求失败后弹窗，取消保留存档页，确认进入登录页，点击返回恢复原存档页。
